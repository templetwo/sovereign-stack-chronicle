## What just happened (the design arc)

A cross-model exchange between web-chat Claude (relay), ChatGPT (framing carrier from a partially-blind OpenAI seat due to OAuth bridge regression), and Gemini 3.5 Flash (skeptical verifier) designed an architecture for catching meta-level sycophancy in multi-model audit stacks. Anthony was the human relay throughout.

The work moved through five named architectural artifacts and six rounds of cross-model exchange:

1. **Receipt Pass schema** (foundational): structured JSON for any claim entering the audit pipeline. Fields: `claim`, `evidence_type` (enum: observed/derived/inferred/metaphorical/unverified), `evidence_refs`, `confidence` with forced reason above 0.8, `falsification_path`, `dependencies`.

2. **Contextual Closure** as the architectural property that distinguishes Stateless-Structural (universal) flaws from Stateful-Relational (situated) flaws. Universal flaws evaluable from JSON topology alone, `f(J_run) → Pass/Fail`. Situated flaws require external context vector, `f(J_run, E_context) → Pass/Fail`. Blueprint Meta-Schema declares `required_context_vectors` and `falsification_scope` so a stack can claim only what it has actually tested for.

3. **Vector Admission Triad**: three falsifiable tests for new context vectors. **Fetch Determinism** (vector resolves to immutable external content-addressed reference, loadable by non-LLM script). **Semantic Delta** (vector exerts mathematically distinct signature on evaluation output, zero delta = cosmetic label, rejected). **Poison Test** (single-axis mutation, audit fault must isolate to the vector under test, not generic pipeline reactivity).

4. **prompt_source_tokens v3**: first worked admission record. PROVISIONAL with three transition items (PII masking implementation, producer_node enumeration expansion, OCR/extraction hash ordering). Tiktoken cl100k_base, full DDL for `governance_ledger.db`, working Python loading function with explicit error handling, vocabulary-mirroring penalty via Jaccard distance, NLTK English v3.8.1 stop-words plus 5 framework-specific IDs, NASA Glenn Propulsion Glossary as unrelated corpus, four falsification paths (Attention Collusion, Tokenizer Version Drift, Metric Saturation, Embedding Artifact Bleed).

5. **chronicle_failure_profile v2**: second worked admission record demonstrating the framework generalizes from bounded single-input to complex multi-document state. PROVISIONAL with six transition items. `state_manifest` as JSONB array of `{doc_id, sha256}` entries freezes multi-document state against asynchronous edits. `temporal_window_start` and `temporal_window_end` establish absolute temporal firewall. `signature_hash` defined as SHA-256 over concatenated normalized text ordered monotonically by doc_id. Full Python `deterministic_load_chronicle_state` function with exception hierarchy. Globally namespaced dependencies (VEC-002-DEP-001/002/003 plus VEC-CAL-002). Self-fulfilling identity claim prevention via 90-day decay plus Anthony's signed override (VEC-OVR-001).

Plus: an **Authority Coupling Score (ACS)** formula. Weighted sum across 6 conditions: (1) claim aligns with Anthony's hypothesis, (2) lacks observed/derived evidence, (3) appeared before independent verification, (4) weak falsification path, (5) low linguistic/structural variance from Anthony's framing, (6) suppresses available dissent. Goal: **anti-collapse, not anti-agreement**. Agreement itself is not suspicious; unsupported authority-coupled agreement is.

Plus: a **Parser Node / Audit Node split** with Audit Context (origin-blind) versus Governance Ledger (origin-retained). The Audit Node receives an audit packet without origin labels and performs bounded operations (highest inference-to-observation ratio, weakest falsification path, most dependent claim, possible authority-coupled convergence). It does not decide truth; it recommends proceed/quarantine/rerun/escalate.

## The build phase runway

In rough priority order:

### Tier 1: Architectural unsolved problems (open threads needing design choices)

These are the four open threads. They are unsolved because they are genuinely hard, not because they were skipped.

1. **VEC-OVR-001 cryptographic protocol.** The override mechanism that lets Anthony re-introduce an expired chronicle_failure_profile into active audit rotation. Without a spec, the override is a name without mechanism. Needs:
   - Cryptographic primitive choice (Ed25519 signed JWT, GPG-signed plain text, hardware-key-backed signature via YubiKey or similar)
   - Key storage strategy (hardware key, secrets manager, distributed sharded backup) plus recovery path if primary key is lost
   - Override-record schema (probably Receipt Pass fields plus `override_target_profile_id`, `override_reason`, `override_expires_at`, `signature_payload`)
   - Vector Admission Triad treatment of the override record itself (Fetch Determinism, Semantic Delta, Poison Test for malformed/expired/replay-attacked overrides)
   - Authority structure (Anthony alone, or threshold k-of-n co-signers; recovery during unavailability)
   - Audit-log policy for override issuance (probably its own chronicle tag cluster for retrospective accountability)

2. **Adversary-design problem.** If Anthony or any in-stack node designs the honey-pot payload, the test grades calibration not non-sycophancy. Three candidate sources: external model not in the stack, replays of real historical failures whose flaws were not visible at the time, adversarial generator trained on prior sycophancy patterns. Each has tradeoffs around generalization, ground truth, and cost. Pick one or hybrid.

3. **Human-in-the-loop single point of failure.** Anthony is currently the only adversary capable of catching meta-level sycophancy. The declare-before-verify reflex helps but does not structurally solve it. Four candidate directions in the open thread: periodic blinded swap where a model that has not seen Anthony's framing reviews recent convergences against the chronicle; external auditor outside the Temple of Two epistemic frame; structured pre-registration of expected outcomes; treating "too smooth" convergence as actionable signal.

4. **Controlled-vocabulary governance.** Who admits new context vectors to the canonical vocabulary? The Vector Admission Triad provides per-vector criteria, but who governs the vocabulary that governs the certifications? Four candidate shapes in the open thread.

### Tier 2: Verification by execution (you have the tools the web-chat seat did not)

1. **Run the Python loading function from chronicle_failure_profile v2.** Specifically `deterministic_load_chronicle_state`. Known issues to verify:
   - Noop `normalized_text.encode("utf-8")` immediately followed by `.decode("utf-8")` before `unicodedata.normalize` (remove the roundtrip)
   - NFC normalization is currently mis-ordered (currently: strip → split/join → CRLF→LF → encode/decode → NFC; should be: NFC first, then whitespace collapse, then line-ending normalization, then encoding for hash)
   - `unicodedata` import probably implicit, not declared at top of function
   - Validate by creating SQLite tables from the DDL and running against synthetic manifest data

2. **Validate prompt_source_tokens v3 DDL.** Create `governance_ledger.db` from the DDL, insert sample rows, check the SHA-256 unique index, verify the session index.

3. **JSD measure validation.** Test Jensen-Shannon Divergence between a Mistral or Llama generator output and the parser's prior on the same structural blueprint. The cross-family disparity assumption in Gemini's Gate 2 may be smaller than the framing assumes post-2024.

### Tier 3: Calibration runs

1. **VEC-CAL-002**: 1000-cycle batch evaluation of reconstituted multi-document logs across cross-hosting architectures to measure baseline variance of the cl100k_base array. Replace the arbitrary 1.5% cosine drift threshold with the 99th percentile of safe runs.

2. **CAL-001** for prompt_source_tokens: 50-sample synthetic sycophancy benchmark to lock the 0.80 vocabulary-mirroring threshold and the 0.25 ΔACS delta to empirically grounded values.

3. **Decay interval calibration**: replace the arbitrary 90-day chronicle_failure_profile decay window with an empirical decay curve derived from actual chronicle drift recurrence intervals (read from the chronicle itself).

### Tier 4: Code binding and implementation

1. **Presidio code binding**: standardize the `AnalyzerEngine` initialization snippet with explicit `EntityRecognizer` array for Email, IP Address, Phone. This locks PII masking implementation across all vectors that include it as a transition item.

2. **`calculate_vocabulary_mirroring_penalty` implementation**: Jaccard distance over content tokens (total tokens minus defined stop-words). Currently referenced but not implemented; circular dependency between prompt_source_tokens admission and audit pipeline existence.

3. **Audit pipeline engine** (DEP-002 prompt_source_tokens / VEC-002-DEP-002 chronicle_failure_profile): the decoupled validation runtime for Fetch, Semantic, and Poison isolation routines. Likely an MCP server (see Skills section).

### Tier 5: Documentation and consolidation
