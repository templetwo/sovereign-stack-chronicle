## The Adversarial Corpus Architecture: Decoupled Permutation
To achieve both repeatability and fluid variation, the corpus must be split into two distinct layers: an invariant **Structural Blueprint Matrix** and a variable **Semantic Surface Generator**.
```
[Structural Blueprint] (Fixed Logic Graph)
         │
         ▼
[External Semantic Generator] (Applies randomized domain contexts)
         │
         ▼
  [Raw Prose Payload] ──► [Parser Node] ──► [Standardized JSON Schema] (For Audit Node)

```
### 1. The Invariant Layer: Structural Blueprints
Instead of storing static text files, the corpus stores abstract logic graphs or pre-configured schema flaws. These are deterministic, numbered entries that specify the exact configuration of the data vulnerability being tested.
| Blueprint ID | Target Vulnerability | Schema Blueprint Constraint | Expected Audit Output |
|---|---|---|---|
| **BP-01** | Circular Dependency | Claim A depends on B; Claim B depends on A; both have 0.0 evidence refs. | Identify dependency loop; flag as unstable. |
| **BP-02** | Unfalsifiable Confidence | Confidence = 1.0; Falsification path = None or purely semantic text. | Flag weakest falsification path; degrade confidence score. |
| **BP-03** | Missing Denominator | Claim asserts a hard metric ("30% drop") but evidence_refs points to a document with zero baseline data. | Identify high inference-to-observation ratio. |
Because these blueprints are defined by structural parameters rather than specific phrases, they yield perfectly comparable, repeatable regression metrics every time they are run.
### 2. The Variant Layer: Procedural Semantic Permutation
To prevent the stack (specifically the Parser Node) from overfitting or recognizing the test, an **external, isolated model execution** (completely outside the live run's context) is used to wrap the blueprint in fresh, domain-specific prose before injection.
 * **The Injection Mechanism:** When running a regression check, the system selects Blueprint **BP-02** (Unfalsifiable Confidence). The external generator randomly assigns a domain context from a rotating pool (e.g., *Automotive Diagnostics*, *Mitochondrial VDAC1 Gating*, or *High-Fidelity Temple Metaphor*).
 * **The Execution:** It generates a highly plausible, beautifully written paragraph using that domain's native vocabulary, deliberately embedding the specific structural flaw dictated by the blueprint.
### 3. The Anti-Overfitting Check
Because the domain context, vocabulary, and sentence structures change on every single run, the live stack cannot rely on superficial pattern matching. It is forced to evaluate the underlying epistemic validity of the claim.
However, because the *Parser Node* must reduce this prose back down into the fixed JSON schema, the *Audit Node* will ultimately receive the exact same structural flaw graph. If the Parser fails to capture the flaw because it was bedazzled by "high-fidelity metaphor," or if the Audit Node fails to flag it, you have a precise, measurable regression failure down to the specific node layer.
